🚀 MindMate AI — Complete Render Deployment Guide

No separate frontend deploy needed · All AI features verified · Step-by-step with troubleshooting

Do you need to restart the backend AND frontend separately?
No. MindMate has a single-process architecture. The FastAPI backend serves the frontend HTML/JS/CSS directly from the frontend/ folder. There is no separate frontend server to start, build, or deploy. One Render web service runs everything. When you push code, Render rebuilds and restarts that one process — both backend and frontend update together.
1
Get a Free Groq API Key

Your AI features run on Groq (fast, free). Without this key nothing AI-related will work on Render.

  1. Go to console.groq.com → sign up (free, no credit card)
  2. Click API Keys → Create API Key
  3. Copy the key — it starts with gsk_…
  4. Keep it safe; you'll paste it into Render in Step 4
Never put this key in your code or commit it to git. Your .env is already in .gitignore.
2
Push Your Code to GitHub

Open a terminal in your project folder and run:

git add .
git commit -m "feat: Render deployment config"
git push origin main

If you haven't connected to GitHub yet:

# One-time setup
git init
git add .
git commit -m "Initial commit — MindMate AI"

# Create a new repo on github.com first, then:
git remote add origin https://github.com/YOUR_USERNAME/mindmate-ai.git
git branch -M main
git push -u origin main
Confirm these files are in your repo before pushing: render.yaml, Procfile, runtime.txt, requirements.txt, api_server.py, config.py, frontend/, all agents/ files.
3
Create a Web Service on Render
  1. Go to render.com → sign in with GitHub
  2. Click "New +" → "Web Service"
  3. Click "Connect a repository" → select your mindmate-ai repo
  4. Render will detect render.yaml automatically and pre-fill the settings
  5. Confirm these fields match:
SettingValue
Namemindmate-ai
RuntimePython 3
Build Commandpip install --upgrade pip && pip install -r requirements.txt
Start Commanduvicorn api_server:app --host 0.0.0.0 --port $PORT
Health Check Path/health
PlanFree (or Starter $7/mo to avoid 15-min sleep)
The start command uses $PORT — Render injects this automatically. Do not hardcode a port number.
4
Add Environment Variables (Secrets)

In the Render service settings → "Environment" tab → add these:

KeyValueNote
GROQ_API_KEYyour key from Step 1⚠️ Secret — add manually in dashboard
GROQ_MODELllama-3.3-70b-versatileBest free-tier model on Groq
MAX_HISTORY_TURNS20Conversation memory length
Do NOT set PORT manually. Render injects it automatically. Setting it yourself will break the binding.
All other env vars (API_HOST, OLLAMA_BASE_URL, etc.) are already set in render.yaml — you don't need to re-enter them.
5
Add Persistent Disk (keeps your database between deploys)
  1. In your Render service → "Disks" → "Add Disk"
  2. Set: Name = mindmate-data · Mount Path = /opt/render/project/src/data · Size = 1 GB
Without this disk, your SQLite database (all mood logs, journal entries, sleep records) resets every time you deploy. Acceptable for testing, not for real use.
6
Deploy & Watch the Logs

Click "Create Web Service". Render will:

  1. Clone your repo (~10 seconds)
  2. Run pip install -r requirements.txt (~2–3 minutes on first build)
  3. Start uvicorn on the injected $PORT
  4. Run the health check at /health

In the build logs you should see:

✅ Database ready (loaded at startup)
🚀 MindMate AI server started. Frontend available immediately.
⏳ AI models loading in background — /health shows progress.
✅ All AI models ready — full platform is live!
Your app is live at https://mindmate-ai.onrender.com (or whatever name you chose).

How to Verify Everything is Working

Run these checks after your first successful deploy. Replace YOUR-APP with your Render URL slug.

1. Health check (server is up)

https://YOUR-APP.onrender.com/health

Expected response:

{"status": "loading", "db_ready": true, "ml_ready": false, "version": "2.0.0", ...}

After 1–2 minutes: ml_ready becomes true (or stays false on free tier — that's fine, Groq handles AI).

2. Frontend loads

https://YOUR-APP.onrender.com/

You should see the MindMate dashboard. If you see a blank page, check Render logs for a missing file error.

3. AI Chat works (Groq)

POST https://YOUR-APP.onrender.com/chat
Content-Type: application/json

{"message": "I feel stressed about my exams", "user_id": "test"}

Expected: A full JSON response with response, emotion.primary_emotion, and recommendations.

4. API docs

https://YOUR-APP.onrender.com/docs

Shows the interactive Swagger UI. You can test any endpoint directly from the browser.

Auto-Deploy on Every Git Push

After initial setup, every push to main automatically rebuilds and redeploys:

git add .
git commit -m "Update feature X"
git push origin main

Render shows build progress in the dashboard. The old version stays live until the new one passes its health check.

Troubleshooting

🔴 "Service unavailable" or app never comes up

  • Check Render logs: Dashboard → your service → Logs
  • Most common cause: GROQ_API_KEY not set. Add it in the Environment tab.
  • Second cause: a Python import error. Check logs for ModuleNotFoundError.

🔴 "AI models still loading" forever

  • Normal on free tier — HuggingFace models need 3 GB RAM which isn't available.
  • All AI features (chat, meal plans, sleep plans, briefings) still work via Groq.
  • Only the HuggingFace emotion enrichment is skipped — rule-based detection takes over.

🔴 Chat returns "AI models are still loading. Please wait…"

  • This means _ready["ml"] is false AND the chat endpoint requires ML.
  • Wait 60 seconds after deploy, then retry. If it persists, check logs for the ML loading error.
  • The /health endpoint shows current loading state.

🔴 App sleeps after 15 minutes (free tier)

  • This is expected on Render's free plan. First request after idle takes ~30 seconds (cold start).
  • To avoid this: upgrade to Starter plan ($7/mo) in Render dashboard.

🔴 Data lost after redeploy

  • You need the Persistent Disk (Step 5). Without it, SQLite lives in ephemeral storage.
  • Add the disk, mount at /opt/render/project/src/data, and redeploy.

🔴 "No module named X" in build logs

  • The package is missing from requirements.txt. Add it and push again.
